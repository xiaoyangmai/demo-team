# Illustrated learning comic

Make the requested principle understandable through what characters do and what changes. Keep the task's topic, audience and output contract; a successful file export is not proof of learning.

1. Plan four beats: an appealing everyday goal, a believable difficulty, a meaningful choice, and its visible consequence. Fix the characters' hair, clothing and a small set of props. Before any image prompt, write a continuity sheet: one fixed object list (identity plus the attributes the lesson compares), then for every panel only the current condition, the one action, and the resulting condition. The next panel starts from that result. An object may not appear, vanish, move, or change group unless that panel's action does it. For scientific comparisons, show the condition that changes and hold other relevant conditions steady. If the sheet contradicts itself, correct the sheet first.
2. Draft all four image prompts from that sheet before generating: use exactly two large ordered panels per page and name the action in each; do not let a familiar four-panel grid override the brief, and do not add objects or group changes the sheet does not list. Generate all four pages with `image_generate` before any repair. Repeat the character and style descriptions, use a successful page as an image reference where the configured tool supports it, and explicitly describe only the new action while the listed objects stay put. With this Hermes local `tool_call` wrapper, submit one `image_generate` entry per call; a multi-entry batch is rejected. Prefer no lettering in the images: short Chinese dialogue belongs in the visible HTML captions. Never substitute diagrams, SVG, emoji or placeholder art for illustrations.
3. Inspect each actual image once with `vision_analyze`, asking only whether the sheet's decisive state is visible: who acted, which listed object moved, and what consequence is on the page. Do not claim a visual check from reading the image prompt, and do not add vision passes in place of a failed state. After all four pages exist, repair at most one defective page if the caller's generation budget still allows it. Copy the returned files into the delivery directory and retain their actual format extensions. Write captions from the checked image, not from an action the picture does not show.
4. Write two application questions with different changed conditions. Each choice is one short action; put the explanation in its feedback. First name the misunderstanding each wrong choice represents. A well-intentioned child could choose it: a useful step at the wrong time, an old rule after the condition changed, or incomplete evidence. Do not use insult/blame/doing-nothing as an easy contrast to the sole kind answer. Compare choices without the answer key: length, politeness and detail should not reveal the correct answer. Feedback explains the decisive condition without inventing a fact absent from the page or question.
5. Give the ending one concise takeaway and one safe, concrete action a child can try today. Avoid a generic moral that could be attached to any story. Use spoken Chinese and follow the caller's reading limits; do not solve ambiguity by making the correct choice a paragraph.
6. Write `lesson.json` and run the bundled `scripts/render.py <delivery-directory>` from this Skill's directory. It packages the four pictures, captions, quiz, retry/reset and completion state; do not rewrite its UI. Check the generated files and the manifest, then write the caller's result receipt with only checks actually performed. Do not edit project/profile files or inspect evaluation material.
