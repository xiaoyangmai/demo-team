# Illustrated learning comic

Make the requested principle understandable through what characters do and what changes. Keep the task's topic, audience and output contract; a successful file export is not proof of learning.

1. Before any image call, plan four beats: an appealing everyday goal, a believable difficulty, a meaningful choice, and its visible consequence. For each beat, list only the decisive objects, who holds or acts on each, the one condition that changes, and an action a still picture can show (an offered hand, an object pulled back, passed, or left unpassed, someone waiting with empty hands). Do not rely on a head-shake, motion line, or spoken request that the drawing may not show. If the principle couples two ideas, each idea needs that kind of visible action; an object that merely stays put, with nobody asking or refusing, is not a choice. Fix hair, clothing, and only the props in this list. Track location and ownership of the object that drives the story. Stop and revise the plan if a later beat contradicts an earlier decisive state, or if the difficulty is a nearby conflict that never shows the principle. For scientific comparisons, show the condition that changes and hold other relevant conditions steady.
2. Draft all four image prompts from that plan before generating: exactly two large ordered panels per page, each naming the planned action. Do not let a familiar four-panel grid override the brief. Generate all four pages with `image_generate` before any repair, one page per call, and count every call toward the caller's generation budget. Repeat the locked character and style descriptions, use one successful page as an image reference where the tool supports it, and describe the new action. If that page omitted a non-decisive prop, leave the prop out of later prompts instead of regenerating to add it. With this Hermes local `tool_call` wrapper, submit one `image_generate` entry per call; a multi-entry batch is rejected. Prefer no lettering in the images: short Chinese dialogue belongs in the visible HTML captions. Never substitute diagrams, SVG, emoji or placeholder art for illustrations.
3. Inspect each actual image once with `vision_analyze`: who acted, what object moved or stayed, and what consequence is visible? Do not claim a visual check from reading the prompt. A change of place or pose is acceptable when ownership and the decisive condition match the plan. Treat a page as defective only if a decisive planned state is missing or contradicted, or the same character is no longer recognizable — not for crop or a small clothing or prop difference. Repair at most one defective page, only after the other three have a first generation, and only if the budget still has a call left. Captions and alt text may state only actions the inspection saw. Copy the returned files into the delivery directory and retain their actual format extensions.
4. Write two application questions with different changed conditions. Each choice is one short action; put the explanation in its feedback. First name the misunderstanding each wrong choice represents. A well-intentioned child could choose it: a useful step at the wrong time, an old rule after the condition changed, or incomplete evidence. Do not use insult/blame/doing-nothing as an easy contrast to the sole kind answer. Compare choices without the answer key: length, politeness and detail should not reveal the correct answer. Feedback explains the decisive condition without inventing a fact absent from the page or question, in the same spoken register as the captions.
5. Give the ending one concise takeaway and one safe, concrete action a child can try today. Avoid a generic moral that could be attached to any story. Use spoken Chinese and follow the caller's reading limits; do not solve ambiguity by making the correct choice a paragraph.
6. Write `lesson.json` and run the bundled `scripts/render.py <delivery-directory>` from this Skill's directory. It packages the four pictures, captions, quiz, retry/reset and completion state; do not rewrite its UI. Check the generated files and the manifest, then write the caller's result receipt with only checks actually performed. The generation count must equal the image_generate calls made, including discarded pages. Do not edit project/profile files or inspect evaluation material.
