# Illustrated learning comic

Make the requested principle understandable through what characters do and what changes. Keep the task's topic, audience and output contract; a successful file export is not proof of learning.

1. Plan four beats: an appealing everyday goal, a believable difficulty, a meaningful choice, and its visible consequence. Fix the characters' hair, clothing and a small set of props. Name one decisive object and write who holds it, where it is, and its configuration at the end of each panel; the next panel starts from that end state. One visible change per panel: do not put a choice and its later result in the same panel, and do not leave the goal as an unshown intention. When a condition changes, change only that condition and keep the same cast, container and other props. For scientific comparisons, show the condition that changes and hold other relevant conditions steady.

2. Draft all four image prompts before generating. Use exactly two large ordered panels per page and name the action in each; do not let a familiar four-panel grid override the brief. In each panel, state the decisive object's incoming state, the single action, and the outgoing state a child could point to, plus what must not move. Repeat the character and style descriptions. Where the configured tool supports it, pass a successful page as a reference for identity and style only; it must not freeze an earlier prop state, and the page is new rather than an edit of the reference. Only the named characters' own hands act — no extra person, limb or second copy of the object. Generate the four pages in order with `image_generate`. With this Hermes local `tool_call` wrapper, submit one `image_generate` entry per call; a multi-entry batch is rejected. Prefer no lettering in the images: short Chinese dialogue belongs in the visible HTML captions. Never substitute diagrams, SVG, emoji or placeholder art for illustrations.

3. Inspect each actual image with `vision_analyze` before accepting it: who acted, where the decisive object is in each panel, and whether that panel's outgoing state is visible and continues the previous end state. Ask for those facts and a yes or no; a prose description is not a pass, and reading the prompt is not a visual check. Cosmetic tilt, expression or background drift is not a failed page. A page fails when the panel count is wrong, the decisive action or consequence cannot be seen or reads as the opposite, the object jumps or duplicates, or an unnamed person or limb appears. Generate each of the four pages once before any retry. If the caller's limit allows one more call, spend that single repair on the failed page that blocks the principle — usually the choice or the consequence — then stop. Do not use further calls to perfect a page that already shows its state, and never exceed the caller's generation limit. Copy the returned files into the delivery directory and retain their actual format extensions. Captions and alt text may state only what the accepted image shows; do not narrate a planned event the picture missed.

4. Write two application questions with different changed conditions. Each choice is one short action; put the explanation in its feedback. First name the misunderstanding each wrong choice represents. A well-intentioned child could choose it: a useful step at the wrong time, an old rule after the condition changed, or incomplete evidence. Do not use insult/blame/doing-nothing as an easy contrast to the sole kind answer. Compare choices without the answer key: length, politeness and detail should not reveal the correct answer. Feedback explains the decisive condition without inventing a fact absent from the page or question.

5. Give the ending one concise takeaway and one safe, concrete action a child can try today. The takeaway must restate the pictured consequence, not a beat the pictures never showed. Avoid a generic moral that could be attached to any story. Use spoken Chinese and follow the caller's reading limits; do not solve ambiguity by making the correct choice a paragraph.

6. Write `lesson.json` and run the bundled `scripts/render.py <delivery-directory>` from this Skill's directory. It packages the four pictures, captions, quiz, retry/reset and completion state; do not rewrite its UI. Check the generated files and the manifest, then write the caller's result receipt with only checks actually performed. Count every `image_generate` call, including discarded ones. Do not edit project/profile files or inspect evaluation material.
