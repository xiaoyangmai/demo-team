# Illustrated learning comic

Make the requested principle understandable through what characters do and what changes. Keep the task's topic, audience and output contract; a successful file export is not proof of learning.

1. Before any image call, plan all four beats: an everyday goal, a believable difficulty, a meaningful choice, and its visible consequence. For each beat name one visible fact that makes the intended decision correct and rules out a plausible wrong reading. That fact must read in a still: where the key object ends and who, if anyone, is touching it—not an ambiguous shared pose. Keep only the cue or relation that fact needs; drop other props. When a classification rule changes, include an object the old rule and the new rule would place differently, and show the current cue. On any other topic use that topic's own decisive condition, not a sorting setup. For a scientific comparison, change one condition and hold the others steady. Fix hair, clothing and the prop set, and track who holds the key object and where it rests. One frozen moment per panel; the next panel begins from the previous end state and must not rewind it.

2. Draft all four prompts before generating. Exactly two large ordered panels per page, one action each; do not let a four-panel grid override the brief. Put each panel's decisive end state in its first lines, then one compact repeated line for character, style, and the key object's fixed shape, color and markings. With this Hermes local `tool_call` wrapper, submit one `image_generate` entry per call; a multi-entry batch is rejected. A rejected or empty call is not a page. Do not repair or stop while fewer than four pages exist. Pass a source image only to edit that same page: any source image is sent as an edit, so an earlier page locks its poses and locations. No decorative lettering; a symbol may stay only as the rule cue. Short Chinese belongs in the HTML captions. Never substitute diagrams, SVG, emoji or placeholder art for illustrations.

3. After four pages exist, repair at most one page—the one whose object state most hides the decisive fact—and only inside the caller's generation budget. A failed repair ends that attempt, not the deliverable: keep the clearer file for that page. Do not reorder pages so a later state stands in for an earlier beat. Inspect the kept images with `vision_analyze`: who acted, where the key object is, and whether the decisive fact is visible. Do not claim a visual check from the prompt. Write alt text and captions only for relations the image shows; a caption may name a supported relation but must not invent a handoff, placement or consequence. Copy the returned bytes into the delivery directory and retain their actual format extensions.

4. Write two application questions with different changed conditions. Do not quiz names. Each choice, including the correct one, is one short action of the same kind; put the explanation in its feedback. First name the misunderstanding each wrong choice represents. A well-intentioned child could choose it: a useful step at the wrong time, an old rule after the condition changed, or incomplete evidence. Do not use insult, blame or doing-nothing as an easy contrast to the sole kind answer. Compare choices without the answer key: length, politeness and detail should not reveal the correct answer. Feedback explains the decisive condition without inventing a fact absent from the page or question.

5. Give the ending one concise takeaway and one safe, concrete action a child can try today. Avoid a generic moral that could be attached to any story. Use spoken Chinese and follow the caller's reading limits; do not solve ambiguity by making the correct choice a paragraph.

6. Write `lesson.json` and run the bundled `scripts/render.py <delivery-directory>` from this Skill's directory. It packages the four pictures, captions, quiz, retry/reset and completion state; do not rewrite its UI. Check the generated files and the manifest, then write the caller's result receipt with only checks actually performed. Do not edit project/profile files or inspect evaluation material.
